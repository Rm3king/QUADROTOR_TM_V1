# 飞控项目重构上下文文档

## 1. 项目目标

- 项目类型：轻量化嵌入式飞控，语言以 C 为主。
- 当前主要问题：
  - 全局变量较多。
  - 不同文件风格不统一。
  - 命名混乱，存在“函数名与实际硬件映射不一致”的历史问题。
  - 模块职责划分不够清晰。
- 重构目标：
  - 提高可读性、可维护性、风格一致性。
  - 优先保证编译通过、行为一致、便于逐步验证。

## 2. 硬约束

- 不改算法。
- 不改控制流程。
- 不改状态机逻辑。
- 不改参数含义。
- 不改变外部行为。
- 优先兼容现有工程和编译环境。
- 注释统一使用中文。
- 风格适合 TI / 嵌入式 C 项目，不做过度面向对象化。

## 3. 已确认的重构原则

- 重构只改“表达方式”，不改“行为”。
- 每次只处理一个明确主题，不跨多个高风险链路同时改。
- 先低风险模块，后高风险模块。
- 先做注释、命名、接口澄清、私有化收口，再考虑文件拆分。
- 不在工程目录中保留 `old`、`bak`、`new` 备份文件，回退依赖 Git 检查点。

## 4. 统一规范摘要

### 4.1 文件组织

- 一个模块原则上对应一对 `.c/.h`。
- `Application`：任务编排、通信协议、业务控制。
- `Driver`：板级外设驱动。
- `Driver/SenserDriver`：具体传感器与外部模块驱动。
- `SRC/fc_general`：飞控通用基础能力。
- `SRC/fc_specific`：飞控控制与状态逻辑。

### 4.2 命名

- 函数命名统一为“模块前缀 + 动作 + 对象”。
- 避免无语义缩写，保留行业固定缩写：IMU、UART、PWM、RC、PID、GPS。
- 对历史错误命名，不直接粗暴改旧接口，先加语义明确的兼容包装名。

### 4.3 全局变量

- 新增跨模块全局量必须只有一个定义点。
- 优先把同类状态收敛到结构体，不新增零散裸全局。
- 中断与主循环共享数据，明确是否需要 `volatile`。

### 4.4 静态变量

- 文件私有函数和变量优先使用 `static`。
- 文件内静态变量建议使用 `s_` 前缀。
- 函数内 `static` 仅用于必须跨调用保留状态的场景，并补中文说明。

### 4.5 宏、枚举、结构体

- 常量宏使用全大写下划线。
- 枚举值带主题前缀。
- 新增类型名统一使用 `_t` 后缀。
- 尽量减少带副作用宏。

### 4.6 注释

- 说明职责、时序、单位、约束、风险，不写空话。
- 模块头部说明“职责、对外接口、调用周期、依赖关系”。
- 关键函数说明“功能、输入输出、调用频率、是否可在中断中调用”。

### 4.7 函数职责

- 普通函数建议不超过 60 行。
- 超长函数拆成静态子函数，但必须保持原调用顺序不变。
- 一个函数只做一类事情，不混合采集、判定、输出、通信。

### 4.8 头文件依赖

- `.c` 文件优先先包含自己的 `.h`。
- `.h` 只包含声明所必需的内容。
- 能前置声明就前置声明，减少传递依赖。
- 头文件中不定义可写全局变量，只做声明。

## 5. 风险分级

### 5.1 低风险可先做

- 通信协议打包与解析。
- LED / USB / 状态指示。
- 参数映射整理。
- 命名与接口语义澄清。
- `static` 收口。
- 中文注释补全。
- 头文件依赖整理。

### 5.2 暂时不要动或必须极谨慎处理

- 中断入口与中断共享数据。
- 调度器与系统时基。
- 姿态解算。
- 飞行状态机。
- 电机混控与 PWM 输出。
- RC 解码。
- Flash 参数存储时序。
- 核心传感器驱动。

## 6. 执行守则

- 一轮只改一个明确模块或一个明确主题。
- 每轮改动都要能描述清楚边界。
- 每轮都保留可回退的 Git 检查点。
- 发现命名与硬件映射不一致，先补映射说明，再加兼容接口，再逐步迁移。
- 高风险代码不做“顺手优化”。
- 只要验证不稳，就停在当前轮，不叠加更多改动。

## 7. 阶段计划

### 阶段 0：基线固化

- 建立模块清单、风险清单、命名问题清单。
- 建立串口逻辑名与物理 UART 映射表。
- 建立任务周期与关键入口表。
- 打基线提交或标签。

### 阶段 1：低风险风格与接口整理

- 目标：先统一风格，不碰飞控核心行为。
- 范围：
  - `Application/Ano_DT.*`
  - `Application/Ano_LED.*`
  - `Application/Ano_Usb.*`
- 主要动作：
  - 模块说明补全。
  - 命名统一。
  - 重复代码提取。
  - 私有函数与变量 `static` 收口。
  - 头文件公共接口收敛。

### 阶段 2：接口语义澄清

- 目标：解决“函数名和真实硬件映射不一致”的问题，但先兼容旧工程。
- 范围：
  - `Driver/Drv_Uart.*`
  - `Driver/Drv_RcIn.*`
  - 必要时补充板级接口说明。
- 主要动作：
  - 建立统一映射说明。
  - 新增语义明确的兼容别名。
  - 保持旧接口可用，不直接破坏现有调用点。

### 阶段 3 以后

- 再考虑参数层、应用控制层、调度层文档化。
- 控制链、执行链、时序链最后处理。
