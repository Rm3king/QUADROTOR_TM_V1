# 第二阶段重构目标清单

## 1. 阶段目标

第二阶段不再以“清注释、清乱码”为主，而是进入更深一层的工程化整理。

核心目标：

- 在不改算法、不改流程、不改状态机、不改参数含义的前提下
- 继续统一命名、接口和模块边界
- 让代码更接近“可长期维护”的工程状态

---

## 2. 优先级

### 第一优先级：外设与接口语义统一

- 串口驱动命名统一
- RC 输入接口语义统一
- 历史编号接口保留兼容层
- 新代码优先使用语义化接口名

### 第二优先级：全局状态治理

- 明确共享状态归属
- 区分参数层、飞行状态层、驱动层、中断共享层
- 减少裸全局的扩散

### 第三优先级：大文件内部结构收拢

- 只拆文件内 `static` 子函数
- 不改调用顺序
- 不改状态推进条件

### 第四优先级：命名词表统一

- `target / ref / feedback / output`
- `raw / filt / fus`
- `init / reset / update / apply / decode / send`

### 第五优先级：信号流文档化

- RC 输入链
- 姿态链
- 高度链
- 位置链
- 电机输出链
- 视觉 / 光流 / GPS / UWB 接入链

---

## 3. 本阶段明确要做的事

1. 把 `Drv_Uart` 改成“语义接口为主，旧编号接口兼容保留”
2. 继续收口 `RC` 与 `Parameter / FcData` 的共享状态命名
3. 继续拆分 `DT`、`FlightCtrl` 这类大文件中的局部职责块
4. 给关键模块补“输入 -> 处理 -> 输出”的说明

---

## 4. 本阶段暂时不做的事

- 不改中断逻辑
- 不改寄存器配置顺序
- 不改任务调度频率
- 不改姿态解算公式
- 不改控制律和限幅策略
- 不改电机混控逻辑
- 不改参数默认值和保存时机

---

## 5. 第二阶段第一轮

第一轮选择：

- `Platform/Peripheral/Drv_Uart.c`
- `Platform/Peripheral/Drv_Uart.h`

本轮目标：

- 让串口接口名能直接表达真实用途
- 保留 `Drv_Uart1~5*` 旧接口，避免影响现有工程
- 不改实际 UART 基址、GPIO 复用和中断处理流程
